# Подготовка сцены

[English](../en/scene-setup.md) · **Русский**

Относится к: MapUploader `feature/2.0/3.0` · Unity 6000.3.19f1 · скриншоты 26.10.2026

Соберите сцену Unity, из которой MapBuilder делает карту: папку и сцену карты, модели, материалы, коллайдеры, динамические объекты, LOD-группы и источники света. Сделайте это до того, как добавлять маркеры, и возвращайтесь сюда всякий раз, когда проверка указывает на сцену.

## Перед началом работы

- Проект MapUploader, открытый в Unity 6000.3.19f1. См. [Начало работы](getting-started.md).
- 3D-модель карты в формате, который импортирует Unity, например FBX.

<a name="scene"></a>
## Создание папки и сцены карты

Храните всё, что относится к одной карте, в отдельной папке внутри `Assets/MapResources/`: сцену, модели, материалы, а позже и настройки карты. MapBuilder сам добавляет сцены из этой папки в список сцен сборки Unity.

Чтобы создать папку и сцену карты:

1. В окне **Project**, в папке `Assets/MapResources/`, создайте папку с названием карты, например `MyTrack`.
1. Откройте эту папку и выберите **Assets** > **Create** > **Scene** > **Scene**.
1. Назовите сцену, используя только буквы, цифры и `_` и начав имя с буквы, например `MyTrack`.
1. Откройте сцену.

Результат: открыта сцена `Assets/MapResources/MyTrack/MyTrack.unity`, и она есть в списке сцен сборки Unity.

Если сцена названа иначе, проверка останавливает сборку с ошибкой, которая начинается с `The scene name '<name>' cannot be used for a build.` <!-- src: Assets/Editor/Validation/MapMetaValidator.cs:37-41 -->

Пример TestMap показывает типичное устройство папки карты:

```text
Assets/MapResources/TestMap/
├─ Art/                  модели, материалы и текстуры
├─ EnvironmentProfiles/  запечённый reflection probe для предпросмотра в редакторе
├─ Graph/                шейдеры Shader Graph для растительности
├─ Icon/                 изображения мини-карты, иконки и превью
├─ TestMap.unity         сцена карты
└─ TestMapConfig.asset   настройки карты, создаются позже кнопкой + Новая карта (+ New map)
```

### Как устроен список сцен сборки

Список **Сцена** (Scene) на вкладке **Сборка** (Build) окна MapBuilder показывает только сцены, включённые в списке сцен сборки Unity. MapBuilder сам ведёт этот список:

- Он добавляет в список каждую сцену из `Assets/MapResources` во включённом состоянии — каждый раз, когда редактор загружается или перекомпилирует скрипты, а также когда такую сцену создают или сохраняют.
- Каждый раз, когда Unity сохраняет или создаёт ассет, MapBuilder удаляет из списка все выключенные сцены. Каждый раз, когда ассет перемещают или удаляют, он удаляет выключенные сцены за пределами `Assets/MapResources`, а выключенные сцены внутри этой папки снова включает. Выключенная сцена из `Assets/MapResources` также возвращается в список включённой при следующей загрузке редактора или при сохранении этой сцены.
- Чтобы окончательно убрать сцену из списка **Сцена**, перенесите её за пределы `Assets/MapResources`, а затем выключите её в списке.
- Сцену за пределами `Assets/MapResources` MapBuilder сам не добавляет. Добавьте её в **File** > **Build Profiles** > **Scene List** и оставьте включённой.

Для каждой карты в списке **Сцена** изначально выбрана сцена последней сборки этой карты. До первой сборки выбрана сцена, которая была активной, когда вы выбрали карту. Если этой сцены нет в списке, выбрана первая сцена списка.

<a name="import"></a>
## Импорт моделей

Сборка читает меши, которые импортировал Unity, а не ваши исходные файлы. Подходит любой формат, который импортирует Unity, например FBX, OBJ или DAE.

Чтобы импортировать модель:

1. Перетащите файл модели из файлового менеджера в папку `Assets/MapResources/<MapName>/` в окне **Project**.
1. Перетащите импортированную модель из окна **Project** в окно **Hierarchy**.
1. Сохраните сцену сочетанием клавиш <kbd>Ctrl</kbd>+<kbd>S</kbd>.

Результат: модель видна в окне **Scene**.

Что сборка берёт из моделей и текстур:

- Каждый меш с позициями, нормалями, цветами вершин и одним набором UV — UV0. Другие наборы UV, например UV для лайтмапов, не экспортируются.
- Настройку отбрасывания теней у каждого MeshRenderer: если для **Cast Shadows** выбрано **Off**, меш не отбрасывает тень в игре.
- Каждую текстуру в том размере, в каком её импортировал Unity, считанную без сжатия. Разрешение экспорта ограничивает параметр текстуры **Max Size**; её настройки сжатия на него не влияют.

Включать **Read/Write** для моделей и текстур материалов не нужно. Сборка включает этот параметр на время работы, а затем восстанавливает ваши настройки импорта. Для иконки и превью правила другие; см. [Требования к изображениям](minimap-and-images.md#images).

**Unity Terrain не экспортируется.** Terrain и TerrainCollider не входят в число поддерживаемых компонентов: проверка выводит для каждого из них заметку категории Components, а сборка его пропускает. Маркер Road на Terrain проходит проверку, но в игре у ландшафта не будет столкновений. Вместо этого сделайте землю мешем с MeshCollider; земля в примере TestMap — меш с именем `terrain`.

> [!TIP]
> Храните рабочие файлы 3D-редактора, например `.blend` или `.max`, за пределами `Assets/`, а в проект кладите только экспортированную модель. Unity импортирует каждый файл в `Assets/`, а файл `.blend` может импортировать, только если установлен Blender.

<a name="materials"></a>
## Настройка материалов

Используйте материалы HDRP/Lit. Сборка читает фиксированный набор их параметров и преобразует их для игры — одинаково для Binary и Wavefront.

Чтобы настроить материал:

1. Необязательно: если материалы встроены в модель, Unity не даёт их редактировать. Выберите модель в окне **Project** и в окне **Inspector**, на вкладке **Materials**, нажмите **Extract Materials**, затем выберите папку `Assets/MapResources/<MapName>/`.
1. Необязательно: если у модели нет материалов, откройте папку `Assets/MapResources/<MapName>/` в окне **Project** и выберите **Assets** > **Create** > **Material**.
   Новый материал использует шейдер HDRP/Lit.
1. В окне **Project** выберите материал.
1. В окне **Inspector**, в разделе **Surface Options**, задайте **Surface Type**, **Alpha Clipping** и **Double-Sided**.
1. В разделе **Surface Inputs** назначьте **Base Map**, **Mask Map** и **Normal Map**.
1. Необязательно: в разделе **Emission Inputs** назначьте **Emissive Map** и задайте для неё любой цвет, кроме чёрного.
1. Перетащите материал на объект в окне **Scene**.

Результат: в окне **Scene** объект отображается с этим материалом.

На скриншоте — `Assets/MapResources/TestMap/Art/0x4F368125.mat`, материал HDRP/Lit из примера TestMap, с параметрами, которые читает сборка.

<img src="../images/shared/scene-hdrp-lit-material.png" width="460" alt="Скриншот материала HDRP/Lit в окне Inspector; маркеры 1–5 на Surface Options, Base Map, Mask Map, Normal Map и Emissive Map.">

| # | Элемент | Назначение |
| --- | --- | --- |
| 1 | **Surface Options** | Если включено **Alpha Clipping**, материал экспортируется как cutout. Иначе всё решает **Surface Type**: **Opaque** или **Transparent**. **Double-Sided** и его **Normal Mode** тоже экспортируются. |
| 2 | **Base Map** и её цвет | Экспортируются как diffuse-текстура и цвет. В материале cutout или transparent их альфа становится непрозрачностью. |
| 3 | **Mask Map** | Канал R экспортируется как metallic, а A (smoothness) — как roughness, 1 − A. Каналы G (ambient occlusion) и B (detail mask) игнорируются. |
| 4 | **Normal Map** и её сила | Экспортируется как карта нормалей в касательном пространстве, сила запекается в неё. |
| 5 | **Emissive Map** и её цвет | Свечение экспортируется, только если цвет не чёрный. При чёрном цвете игнорируется и сама карта. |

Сборка также следует этим правилам:

- **Tiling** и **Offset** у **Base Map** сохраняются, и игра применяет их ко всем картам материала.
- Без **Mask Map** экспортируются значения **Metallic** и **Smoothness**. С **Mask Map** параметры **Metallic Remapping** и **Smoothness Remapping** игнорируются.
- В материале cutout значение **Threshold** у Alpha Clipping запекается в непрозрачность. **Alpha Remapping** экспортируется только для материалов **Transparent**.
- **Blending Mode** не экспортируется: прозрачные материалы всегда смешиваются по альфе.
- Оставьте для **Normal Map Space** значение **TangentSpace**. Карта нормалей в пространстве объекта не экспортируется.
- Оставьте для **Base UV mapping** значение **UV0**. Меши содержат только UV0, поэтому другие наборы UV, а также проекции Planar и Triplanar не воспроизводятся.
- Экспортируются только текстуры Texture2D. Кубическая карта или Render Texture в слоте текстуры пропускается с предупреждением в Console, которое заканчивается на `only Texture2D can be exported. Skipped.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/MtlTextureMapWriter.cs:391 -->
- Всё остальное в материале, например **Detail Inputs**, **Height Map** и **Material Type**, не экспортируется.

Все свойства, которые читает сборка, перечислены в разделе [Экспорт материалов HDRP](reference.md#materials). В сборках Binary маркер Material может заменить материал одним из вариантов render core игры; см. [Замена материалов вариантами render core](markers.md#material).

### Материалы Layered Lit

Материалы HDRP/LayeredLit экспортируются со всеми слоями — от 2 до 4. Каждый слой сохраняет свои **Base Map**, **Mask Map**, **Normal Map**, тайлинг и значения, а материал сохраняет смешивание по **Layer Mask** и **Vertex Color Mode**.

Кнопка **Проверить карту** (Validate map) не проверяет настройки Layered Lit. Сборка останавливается с ошибкой в Console, если материал Layered Lit использует одно из следующего:

- **Use Height Based Blend** или **Main Layer Influence**: `Layered Lit '<material>': '<option>' is not supported by the mod material format.`, где `<option>` — свойство шейдера `_UseHeightBasedBlend` или `_UseMainLayerInfluence`. <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/LayeredPbrWriter.cs:10-25 -->
- **BlendMask UV Mapping** со значением, отличным от **UV0**: то же сообщение с `_UVBlendMask`.
- **Base UV mapping** слоя со значением, отличным от **UV0**: `Layered Lit '<material>': layer <n> requires UV0 mapping for mod export.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/LayeredPbrWriter.cs:65-68 -->

### Другие шейдеры

Сборка читает свойства материала по их ссылочным именам (reference). Материал Shader Graph экспортирует те свойства, которые он предоставляет под именами HDRP/Lit, например `_BaseColorMap`, `_BaseColor`, `_NormalMap`, `_MaskMap` и `_EmissiveColor`. Например, растительность TestMap использует `Assets/MapResources/TestMap/Graph/FoliageSimple.shadergraph`, у текстурного свойства которого задано имя `_BaseColorMap`.

<a name="colliders"></a>
## Добавление коллайдеров

Машины сталкиваются только с коллайдерами, а не с видимыми мешами. Добавьте коллайдер каждой поверхности, по которой машины ездят или в которую врезаются.

Чтобы добавить коллайдер:

1. Выберите объект.
1. В окне **Inspector** нажмите **Add Component** и добавьте MeshCollider, BoxCollider, SphereCollider или CapsuleCollider.
1. Необязательно: чтобы столкновения считались по более простой форме, чем видимый меш, назначьте в поле **Mesh** у MeshCollider низкополигональный меш.

Результат: пока объект выбран, окно **Scene** рисует контур коллайдера зелёным.

Затем добавьте каждому объекту с коллайдером маркер Road на том же GameObject, чтобы игра знала его поверхность. См. [Маркеры дорожных поверхностей](markers.md#road).

Что экспортирует сборка:

- MeshCollider — всегда, когда у него есть меш, даже если компонент выключен или установлен флажок **Is Trigger**. Чтобы исключить такой коллайдер, удалите компонент или назначьте объекту тег `Garbage`.
- BoxCollider, SphereCollider или CapsuleCollider — только если он включён и флажок **Is Trigger** снят.
- Другие коллайдеры не экспортируются. Например, TerrainCollider и WheelCollider пропускаются.
- Физический материал у статических коллайдеров не экспортируется: их поверхность задаёт маркер Road.

Коллайдеру не нужен рендерер на том же объекте. В TestMap видимая геометрия и геометрия столкновений разделены: в `Content/workshop_map_main` объекты `road`, `roadside` и `terrain` есть в двух экземплярах — один как видимый меш, другой как MeshCollider с маркером Road.

Оптимизация сборки нарезает большие статические MeshCollider на секторы. См. [Оптимизация](build.md#optimization).

<a name="dynamic"></a>
## Добавление динамических объектов (Rigidbody)

Объект с Rigidbody становится в игре физическим объектом. В TestMap их два: `Flora/advertising_stand_small_6` и `Flora/advertising_stand_small_7`, у каждого Rigidbody массой 50 на объекте с LODGroup. Ещё один пример — `Assets/ExamplePrefab/Box.prefab`: Rigidbody с дочерним BoxCollider.

Чтобы добавить динамический объект:

1. Выберите корень объекта. Если у объекта есть LODGroup, выберите объект с LODGroup.
1. В окне **Inspector** нажмите **Add Component** и добавьте Rigidbody.
1. В компоненте Rigidbody задайте **Mass** и остальные значения.
1. Убедитесь, что у объекта или его дочерних объектов есть хотя бы один включённый коллайдер.
1. У каждого MeshCollider объекта установите флажок **Convex**. Пропустить этот шаг можно, только если у Rigidbody установлен флажок **Is Kinematic**.

Результат: после нажатия кнопки **Проверить карту** проверка не сообщает об ошибках категории Physics для этого объекта.

Сборка экспортирует массу, линейное и угловое затухание, гравитацию, флаг kinematic, ограничения (constraints), центр масс и инерцию (автоматические или заданные вручную) и начальные скорости. Для каждого включённого коллайдера Rigidbody, включая триггеры, она также экспортирует трение и упругость физического материала коллайдера. На карте может быть до 1000 Rigidbody. <!-- src: Assets/Editor/MapSceneRules.cs:17 -->

Из правил ниже кнопка **Проверить карту** проверяет только **Convex**; кроме того, она проверяет лимит в 1000 Rigidbody. Остальное проверяет сборка и останавливается с ошибкой в Console, если:

- Rigidbody находится в иерархии объекта с LODGroup на любой глубине. Поместите Rigidbody на объект с LODGroup или на одного из его родителей. Сообщение начинается с `Rigidbody '<name>' cannot split an enclosing LODGroup.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/RigidbodyExporter.cs:37-39 -->
- У коллайдера Rigidbody скошенный трансформ — он возникает из-за неравномерного масштаба у родителя повёрнутого объекта. Примените масштаб в модели. Сообщение заканчивается на `has a sheared transform. Apply scale in the model first.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/RigidbodyExporter.cs:63-68 -->
- MeshCollider некинематического Rigidbody не выпуклый: `Rigidbody '<name>': a dynamic MeshCollider must be Convex.` Сборку останавливает и MeshCollider у Rigidbody без меша. <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/RigidbodyExporter.cs:75-76 -->
- Rigidbody находится внутри объекта с маркером Animation. Поместите Rigidbody на корень Animator или на одного из его родителей: `Put Rigidbody on the Animator root or above it; a baked animation cannot contain independent moving bodies.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/SceneFormatCollector.cs:45-46 -->

В следующих случаях в Console только появляется предупреждение, и сборка продолжается:

- **Collision Detection** со значением, отличным от **Discrete**. Игра использует дискретное обнаружение столкновений, поэтому непрерывные режимы не экспортируются.
- Rigidbody без включённого коллайдера. Rigidbody пропускается, а его меши экспортируются как статическая геометрия. Сообщение начинается с `Rigidbody '<name>' was skipped: no enabled supported colliders.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/RigidbodyExporter.cs:94 -->
- Физический материал коллайдера использует **Multiply** в **Friction Combine** или **Bounce Combine**. Игра приближает его средним геометрическим: `Rigidbody '<name>': Multiply material combine uses the Unity Physics geometric mean approximation.` <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/RigidbodyExporter.cs:85-86 -->

Оптимизация сборки оставляет динамические объекты и всё, что под ними, как есть.

В игре динамический Rigidbody ведёт себя как физические объекты окружения самой игры: кузов машины толкает его, а колёса по нему не едут. Кинематический Rigidbody сталкивается как статическая геометрия карты, поэтому по нему можно ездить. В онлайн-комнатах игра синхронизирует динамические объекты между игроками и сопоставляет их по id метаданных карты, поэтому после того как вы свяжете публикацию, соберите карту заново; см. [Обновление публикации](publish.md#update).

<a name="lod"></a>
## Использование LOD-групп

Добавьте объекту LODGroup, как в любом проекте Unity. Сборка экспортирует все уровни, а игра переключает их на расстояниях, которые рассчитываются по размеру группы и высотам переходов.

- У LODGroup может быть не больше 8 уровней. Больше — ошибка проверки, которая останавливает сборку: `'<name>' has <n> LOD levels; at most 8 are supported…` <!-- src: Assets/Editor/Validation/SceneValidator.cs:811-819 -->
- LODGroup с одним уровнем всё равно экспортируется как LOD-группа, поэтому объект исчезает на своём переходе **Culled**.
- LODGroup без рендереров ни на одном уровне получает предупреждение категории Geometry.
- Сборка пересчитывает границы каждой LODGroup, поэтому заданное вручную **Object Size** заменяется.
- Оптимизация сборки оставляет ваши LOD-группы как есть. Вместо этого она может генерировать LOD для объединённой статической геометрии.
- Чтобы сделать LOD-объект динамическим, поместите Rigidbody на объект с LODGroup. См. [Добавление динамических объектов (Rigidbody)](#dynamic).

<a name="garbage"></a>
## Организация сцены

Организуйте иерархию как удобно. У карты может быть сколько угодно корневых объектов, общий родитель не нужен. Сборка экспортирует сцену, выбранную в списке **Сцена** на вкладке **Сборка**. Если открыта другая сцена, MapBuilder предлагает сохранить ваши изменения, а затем открывает нужную сцену.

Чтобы исключить объект из карты:

1. Выберите объект.
1. В окне **Inspector** выберите для **Tag** значение `Garbage`.

Результат: проверка, экспорт и оптимизация сборки пропускают объект и все его дочерние объекты.

Используйте `Garbage` для камер съёмки, референсных мешей и других вспомогательных объектов. В TestMap камеры съёмки лежат внутри корневого объекта `Screen` с тегом `Garbage`; см. [Съёмка изображений с помощью CaptureCamera](minimap-and-images.md#capture). Камера или другой вспомогательный объект вне объекта с тегом `Garbage` добавляет в проверку заметку категории Components.

> [!IMPORTANT]
> Выключение объекта не убирает его из карты: неактивные объекты, выключенные MeshRenderer и выключенные MeshCollider всё равно экспортируются. Вместо этого назначьте объекту тег `Garbage`.

Исключения — источники света, Minimap и всё, что находится внутри Rigidbody: неактивными они не экспортируются.

Префабы необязательны. Сборка не использует префабы Unity: она находит объекты с одинаковыми мешем, материалами и коллайдерами и экспортирует их один раз, как экземпляры. Сохраняйте или распаковывайте экземпляры префабов на своё усмотрение.

Сборка не добавляет, не удаляет и не перемещает объекты в вашей сцене. Она только пересчитывает границы каждой LODGroup. Оптимизация сборки работает с копией в памяти.

<a name="lighting"></a>
## Настройка освещения

Игра использует собственное освещение окружения, например небо и солнце. Из вашей сцены она берёт только источники света Point и Spot.

- Экспортируются только включённые источники Point и Spot на активных объектах, в обоих форматах. Все остальные типы, включая Directional и Area, пропускаются.
- Сборка экспортирует для каждого источника положение, поворот, цвет, интенсивность, дальность, углы конуса, настройки теней и цветовую температуру. Интенсивность она переводит в канделы, умножает на 0,1 и ограничивает значением 5000. <!-- src: Assets/Plugins/CarX.Modding.Creator/Editor/SceneFormatCollector.cs:71-85 -->
- На карте может быть до 500 источников света. <!-- src: Assets/Editor/MapSceneRules.cs:20-21 -->
- Volume (небо, туман, экспозиция), источники Directional и Area и Reflection Probe освещают сцену только в редакторе.
- Запечённые лайтмапы не экспортируются, а оптимизация сборки не объединяет рендереры, использующие запечённый лайтмап. Не запекайте освещение в сцене карты.

> [!NOTE]
> В игре экспортированные источники света включаются только ночью. Проверяйте их ночью, когда [тестируете карту в игре](test-in-game.md).

Чтобы посмотреть карту при освещении игровой трассы:

1. В окне **Project** откройте папку `Assets/Art/Internal/EnvironmentProfiles/<track>/`, например `japan`.
1. Перетащите `<track>.prefab`, например `japan.prefab`, в окно **Hierarchy**.

Результат: окно **Scene** показывает карту с небом и солнцем этой трассы. Префаб содержит глобальный Volume и источник Directional с именем `sunlight`.

Всего 23 пресета, названных по игровым трассам и ночным вариантам, например `ebisu`, `irwindale`, `japan`, `nightClear` и `silverstone`. Пример TestMap использует освещение `japan`.

Пресет добавляет в проверку следующие заметки. Они не блокируют сборку:

```text
'sunlight' is a Directional light. It lights the SDK preview only; the game uses its own sun, so it is not exported.
'Volume' is used only for the SDK preview and is not exported or required.
```

Проверка добавляет заметку для каждого включённого источника Directional и предупреждение о типе источника для каждого включённого источника другого типа, кроме Point и Spot, например Area. Ещё одно предупреждение она добавляет, если в сцене два или больше источников Directional, считая выключенные. <!-- src: Assets/Editor/Validation/SceneValidator.cs:736-758 -->

<a name="reference-scene"></a>
## Знакомство с эталонной сценой

Сцена примера TestMap, `Assets/MapResources/TestMap/TestMap.unity`, показывает полностью настроенную карту. Вот её корневые объекты:

```text
TestMap
├─ SpawnPoint          GameMarkerData SpawnPoint: место появления машины
├─ Marking             дорожная разметка: меш с прозрачным материалом, без коллайдера
├─ japan               освещение для предпросмотра: глобальный Volume и Directional 'sunlight' (не экспортируются)
├─ Content
│  └─ workshop_map_main  карта для езды: дорога, обочины, земля и стены
│                        с MeshCollider и маркерами Road, а также бетонные ограждения
├─ Flora               деревья, кусты, трибуны, билборды, ограждения и вышки в виде LOD-групп;
│                      4 источника Point на radio_tower; Rigidbody на
│                      advertising_stand_small_6 и advertising_stand_small_7
├─ ReflectionProbe     только для предпросмотра (не экспортируется)
├─ Minimap             единственный компонент Minimap карты
└─ Screen              тег Garbage: камеры съёмки PreviewScreen и MinimapScreen
```

Если нажать **Проверить карту** на TestMap, ошибок и предупреждений не будет, только заметки: одна на `sunlight` для предпросмотра и по одной на Volume, ReflectionProbe и HDAdditionalReflectionData, которые нужны только для предпросмотра. См. [Проверка карты](validation.md).
