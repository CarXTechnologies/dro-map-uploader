## Подготовка проекта

1. Получите проект. В репозитории есть **git-сабмодуль** (`Assets/Plugins/CarX.Modding.Creator`), поэтому клонируйте
   его через `git`, а не скачивайте ZIP:

   ```bash
   git clone --recurse-submodules https://github.com/CarXTechnologies/dro-map-uploader
   ```

   > [!WARNING]
   > **Code → Download ZIP** *не* включает сабмодули — папка `Assets/Plugins/CarX.Modding.Creator` останется пустой,
   > и проект не скомпилируется.

   <img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/1.png?raw=true" alt="Скачивание архива проекта" style="width:600px;"/>

2. Установите **Unity Editor 6000.3.19f1** (только 64-бит): **[скачать установщик](https://download.unity3d.com/download_unity/7689f4515d75/Windows64EditorInstaller/UnitySetup64-6000.3.19f1.exe)**.

   > [!IMPORTANT]
   > Версия должна совпадать точно. Она записана в `ProjectSettings/ProjectVersion.txt`, и открытие проекта другим
   > редактором обновит его на месте — это изменение, которого вы не просили и которое непросто откатить.
3. Запустите Unity, выберите **File → Open Project** и укажите папку проекта (в ней должны быть папки `Assets` и
   `Packages`).

После открытия проекта переходите к следующему шагу.

### Обновление уже склонированного проекта

Если репозиторий был склонирован без `--recurse-submodules` или после изменений, затрагивающих сабмодуль:

```bash
git submodule update --init --recursive
```

Чтобы подтянуть всё актуальное, включая сабмодули:

```bash
git pull --recurse-submodules
git submodule update --init --recursive
```

Чтобы полностью сбросить рабочую копию и загрузить всё заново — **это удалит все локальные изменения**, включая
неотслеживаемые файлы:

```bash
git reset --hard
git clean -xffd                     # второй -f удаляет и неотслеживаемые папки сабмодулей
git submodule update --init --recursive --force
```

Если сабмодуль не скачивается по SSH (`git@github.com: Permission denied`), переключите git на HTTPS:

```bash
git config --global url."https://github.com/".insteadOf git@github.com:
git submodule update --init --recursive
```

## Импорт 3D-модели в проект

1. В `Assets/MapResources/` создайте папку с именем вашей карты.
2. Внутри неё создайте сцену через **Assets → Create → Scene**.
3. Перетащите модель `.fbx` / [`.obj`](https://www.autodesk.com/products/fbx/overview) /
   [`.dae`](https://www.khronos.org/collada/) в `Assets/MapResources/<ваша_папка>/`.
4. Если модели пришли без материалов, создайте их через **Assets → Create → Material** и настройте, как показано ниже.

   <img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/2.png?raw=true" alt="Настройка материала" style="width:400px;"/>

5. Откройте созданную сцену и перетащите в неё модель — получится GameObject.
6. Добавьте на этот объект нужные компоненты.
7. Чтобы объект можно было переиспользовать (Prefab), создайте папку `Assets/MapResources/<ваша_папка>/Prefabs`.
8. Нажмите на объекте в сцене правой кнопкой и выберите **Prefab → Unpack Completely**.
9. Перетащите объект из сцены в созданную папку `Prefabs` — теперь его можно использовать сколько угодно раз.

   <img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/3.png?raw=true" alt="Папка Prefabs" style="width:300px;"/>

## Основные компоненты

Проект поддерживает несколько типов компонентов, которые переносятся в игру. Главные из них:

- точка появления машины на карте,
- фоновые звуки,
- физические материалы поверхностей.

Эти компоненты назначаются через помощник **GameMarkerData**. Чтобы добавить его на GameObject или префаб, нажмите
**Add Component** в инспекторе и введите `GameMarkerData`. Также можно добавить мини-карту.

### Настройка поверхностей и столкновений

Для объекта трассы, который является поверхностью, задайте в GameMarkerData тип **Road** и выберите в выпадающем
списке материал, который будет использоваться в игре при взаимодействии с этой поверхностью.

<img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/4.png?raw=true" alt="Настройка маркера дороги" style="width:500px;"/>

> [!NOTE]
> На любом GameObject/префабе со столкновениями должен быть компонент Collider (Box / Sphere / Capsule / Mesh
> Collider). Без него столкновения работать не будут.

### Точка появления машины

Создайте пустой объект через **GameObject → Create Empty** (или <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>). В
компоненте Transform задайте координаты, где машина должна появляться в игре. Добавьте компонент **GameMarkerData** и
выберите тип **SpawnPoint**.

> [!IMPORTANT]
> В формате **dro1** на карте может быть ровно одна точка появления. **dro2** поддерживает несколько — давайте
> объектам осмысленные имена, потому что имя экспортируется вместе с точкой и опознаёт её в игре.

<img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/5.png?raw=true" alt="Настройка точки появления" style="width:400px;"/>

### Фоновые звуки

Создайте пустой объект через **GameObject → Create Empty** (или <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>).
Добавьте компонент **GameMarkerData**, выберите тип **Ambient** и укажите в списке подходящий для карты звук.

<img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/6.png?raw=true" alt="Настройка маркера Ambient" style="width:400px;"/>

Вместе с маркером Ambient можно использовать компонент **DrawZoneBehaviour** — он рисует зону, в которой будут слышны
назначенные звуки.

<img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/7.png?raw=true" alt="Гизмо зоны Ambient" style="width:300px;"/>

Если нужен другой вспомогательный скрипт, напишите свой и добавьте его в `Assets/Resources/MapSkipComponent`.

### Мини-карта

На каждой карте должна быть ровно одна мини-карта. Создайте пустой объект в сцене (как описано выше), добавьте
компонент **Minimap** и выберите Minimap Layer. В **Textures → Element 0** назначьте хотя бы одну текстуру —
MainTexture. При настройке можно воспользоваться вспомогательными функциями: сгенерировать заготовку, открыть её в
графическом редакторе и нарисовать поверх свою мини-карту.

- **Bound center** — смещение мини-карты относительно центра.
- **Bound size** — размер карты в мировых координатах.

> [!NOTE]
> Карта должна быть отцентрована относительно нулевых координат.

<img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/8.png?raw=true" alt="Настройка мини-карты" style="width:800px;"/>

   >
   > <img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/15.png?raw=true" alt="Список сцен в Build Settings" style="width:400px;"/>

3. Создайте конфигурацию карты в папке карты.

   <img src="https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/26.png?raw=true" alt="Создание конфига карты" style="width:600px;"/>

4. Заполните конфигурацию:

   - **Workshop Name** — название карты в Workshop. Буквы, цифры, пробелы и `- _ ' . , : ! ? ( ) & + /`.
   - **Summary** *(необязательно)* — одна строка рядом с картой в списке модов. mod.io требует её и ограничивает

   - **Workshop Description** *(необязательно)* — описание, которое показывается в Workshop.
   - **Icon** — иконка карты в списке карт Workshop внутри игры (нужен включённый Read/Write, только PNG).
   - **Preview** — превью карты в Workshop и при входе на карту в игре (нужен включённый Read/Write, только PNG).

   ![Конфиг карты](https://github.com/CarXTechnologies/dro-map-uploader/blob/target/1.1/Image/16.png?raw=true)

### Формат мода: dro1 и dro2

- **dro1** — исходный формат. Сцена и её мета упаковываются в Unity **AssetBundle**, доступна настройка Compression.

  > [!IMPORTANT]
  > dro1 привязан к **Unity 2023.2.20f1** — версии движка, на которой работает игра. AssetBundle читается только тем
  > движком, который его записал, поэтому dro1-бандл, собранный другим редактором, опубликуется без ошибок, но в
  > игре загрузится пустой картой. Загрузчик поэтому отказывается собирать dro1 из редактора другой версии.
  > Требуемая версия задаётся в `MapManagerConfig` (**Dro1 Editor Version**) и обновляется вместе с игрой, когда та
  > переходит на новый движок.
- **dro2** — новый формат. Карта экспортируется в каталог обычных файлов (obj / mtl / png / json) вместо
  AssetBundle, поэтому она не привязана к версии Unity, которой была собрана. Настройка Compression не используется и
  скрывается при выборе dro2.

📄 Полная документация по dro2: **[DRO2.md](DRO2.md)** — структура выгрузки, правила экспорта мешей, материалов и
текстур, обработка LOD и маркеров, ограничения и разбор проблем.

## Проверка карты

Кнопка **Validate** в разделе Build Settings проверяет карту, ничего не собирая. Сцена при этом не изменяется, так
что запускать проверку можно сколько угодно — это самый быстрый способ понять, готова ли карта.

Те же проверки выполняются автоматически при сборке. В обоих случаях результат открывается в окне **Map Validation**:
всё найденное за один проход, у каждой строки кнопка **Select**, которая переводит к виноватому объекту. В консоль
попадает только одна итоговая строка — кнопка **To console** в окне выгружает туда полный список, а **Copy**
копирует его в буфер обмена.

- **Ошибки** останавливают сборку. Исправляйте все сразу — они специально показываются вместе, чтобы не находить их
  по одной за пересборку.
- **Предупреждения** ничего не останавливают, но каждое означает, что часть вашей работы не дойдёт до игроков.

Что проверяется:

| Область | Проверки |
| --- | --- |
| Мета | Название задано, допустимые символы и длина в пределах лимита площадки; длина описания и summary; иконка назначена, читаема, в PNG и в пределах лимита; превью читаемо и не больше 10 МБ |
| Компоненты | Всё по списку [поддерживаемых компонентов](#поддерживаемые-компоненты) и лимитам на каждый тип; потерянные (удалённые) скрипты |
| Маркеры | Точка появления существует; в dro1 она ровно одна; повторяющиеся имена точек в dro2; маркеры без выбранного типа; маркеры Road без Collider |
| Формат | Всё, что поддерживает dro1, но что сборка dro2 молча выбросит |
| Освещение | Больше одного Directional Light; типы света, которые dro2 не экспортирует |
| Геометрия | Рендереры без меша и с пустыми слотами материалов; MeshCollider без меша; LODGroup больше 8 уровней или без рендереров |
| Физика | Невыпуклый MeshCollider на некинематическом Rigidbody |
| Мини-карта | Bound Size остался нулевым; отсутствующие текстуры или текстуры не типа Texture2D |

Объекты с тегом **Garbage** пропускаются — ровно так же, как при сборке.

## Поддерживаемые компоненты

| Категория | Компоненты |
| --- | --- |
| **Физика** | MeshCollider, BoxCollider, SphereCollider, CapsuleCollider, Rigidbody |
| **Графика** | ReflectionProbe, Volume |
| **Рендер** | MeshRenderer, MeshFilter, Light, LODGroup, ParticleSystemRenderer, VFX particle |
| **UI** | Canvas, RawImage, TextMeshProUGUI |
| **Прочее** | VideoPlayer (1280×720, 30 fps, 15 сек) |

## Требования

- Не используйте несколько источников Directional Light.
- Размер карты — не больше 4 ГБ.
- Размер меты — не больше 24 МБ (включая превью, иконку, описание и название).
- Учитывайте ограничения по компонентам.

Остальные лимиты зависят от площадки, и загрузчик проверяет их по той, которая выбрана:

| Лимит | Steam Workshop | mod.io |
| --- | --- | --- |
| Превью / логотип | 1 МБ | 8 МБ |
| Название карты | 128 символов | 50 символов |
| Описание | 8000 символов | 50000 символов |
| Summary | не используется | обязательно, 250 символов |

- Невыпуклый MeshCollider вместе с некинематическим Rigidbody больше не поддерживается.

Если карта настроена неверно, при загрузке будет показана ошибка — перечисленные причины нужно устранить на своей
стороне.

После выполнения всех шагов карта публикуется на выбранной площадке. Свежезагруженная карта на обеих площадках
**скрытая (private)**, так что её можно протестировать, пока она видна только вам — в Steam откройте в игре
**Workshop → Track Workshop**. Сделать её публичной можно на странице карты на сайте площадки.

> [!WARNING]
> В Steam вариант видимости **Friends Only** сейчас работает некорректно из-за внешней библиотеки для интеграции со
> Steam API. Мы планируем исправить это в одном из ближайших обновлений.
